# 실기 점검표 (사용자가 직접 수행)

실제 로봇을 움직이는 시험은 사용자가 한다. 가짜 로봇 시험을 통과했다고 실기에서도 검증된 것은 아니다. 각 항목에 날짜·결과·메모를 적는다.
준비: 흑갈리와 PuppyPi 를 **같은 Wi-Fi** 에 연결하고, 로봇 주변 1 m 를 비운다. 처음에는 최고 속도 비율을 0.3 으로 낮춘다(연결·설정 화면).

| # | 확인 | 기대 | 날짜 | 결과 | 메모 |
|---|---|---|---|---|---|
| 1 | 연결·설정 → "같은 Wi-Fi 에서 찾기" | 로봇 이름과 IP 가 목록에 나온다(안 나오면 숫자 패드로 IP 입력) | | | |
| 2 | 연결 직후 상태띠 | "대기(중립 확인됨)", RTT 숫자가 보인다 | | | |
| 3 | RT 를 쥐고 왼쪽 스틱을 살짝 앞으로 | 로봇이 천천히 전진, 상태띠 "주행 중" | | | |
| 4 | RT 를 놓는다 | 즉시 정지(로봇 watchdog 0.4 s 이내) | | | |
| 5 | 오른쪽 스틱 좌·우 | 화면 오른쪽 = 로봇 우회전, 왼쪽 = 좌회전 | | | |
| 6 | 후진(스틱 뒤로) | 느리게 후진(로봇 상한 5 cm/s) | | | |
| 7 | 주행 중 Armoury Crate 키 / Alt+Tab | 앱이 포커스를 잃는 즉시 정지 | | | |
| 8 | B(비상정지) | 길게 진동, 상태띠 빨강, 로봇 정지. RT 를 쥐어도 안 움직임 | | | |
| 9 | 오른쪽 아래 "해제: 1초 누르기" | 해제 뒤 RT 를 **한 번 놓았다가** 다시 쥐어야 움직임 | | | |
| 10 | A(서기), D-pad ▲▼(자세) | 자세가 바뀐다. 0.3 초 머문 자세만 전송 | | | |
| 11 | D-pad ◀▶ + LB (wave, sit, stand) | 동작 실행, 상태띠 "동작 실행 중", 그동안 운전 차단 | | | |
| 12 | 노란(큰) 동작: LB 두 번 | 첫 LB 는 안내만, 2 초 안 두 번째 LB 에 실행 | | | |
| 13 | 로봇 화면 "전체 정지"/"전체 해제" | 로봇 전체 latch 와 v2 비상정지의 관계(해제 순서) 기록 | | | |
| 14 | 지도 화면: 짧은 직선(1 m) 그리기 → 경로 보내기 | 제자리 회전 → 이동 → 도착(짧게 두 번 진동) | | | |
| 15 | 경로 중 스틱 건드림 / X | 경로 취소(두 번 진동) | | | |
| 16 | 지도 저장 / 지도 새로 | 결과 메시지, 새로 하면 원점이 지금 위치 | | | |
| 17 | 주행 화면 레이더(Y 로 전환) | 로봇 앞 벽이 레이더 위쪽에 보인다(좌우가 맞는지) | | | |
| 18 | 카메라 | fps·프레임 나이(로그 화면). 끊기면 Wi-Fi 5 GHz 확인 | | | |
| 19 | Wi-Fi 끄기(주행 중) | 로봇이 스스로 멈춘다. 다시 켜면 중립 확인부터 | | | |
| 20 | (선택) 기울여서 운전: 설정에서 켬, RB 쥐고 기울이기 | 앞뒤·좌우 방향이 맞는지. 틀리면 "반대로" 옵션 | | | |
| 21 | 30 분 연속 사용 | 발열, 화면 fps, 배터리 감소 | | | |

측정값을 포트폴리오에 쓸 때는 `docs/MEASUREMENTS.md` 에 날짜·조건(Wi-Fi, 거리, 카메라 켬/끔)·표본 수와 함께 적는다. 로그 화면의 RTT 는 흑갈리 한 기기 시계로 잰 왕복 시간(명령 송신 → ACK 수신)이다. 스틱 입력 → 다리 움직임까지의 지연은 측정하지 않았다.
