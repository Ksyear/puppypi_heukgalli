## 1. v1이 아직 싸 보이는 이유 — 스크린샷 기준 직설 진단

v1은 "기본 ImGui"는 벗어났지만 결과물은 **"데스크톱 툴에 둥근 모서리를 입힌 것"** 이다. 핵심 원인은 다섯 가지이며, 아래 표의 예는 모두 스크린샷에서 직접 확인한 것이다.

## 2. v2 시각 개념: 검은 유리 조종석(Black Glass Cockpit)

**한 문장**: 카메라 또는 LiDAR 지도가 **1280×720 전체**를 채우고, 조작은 그 위에 **떠 있는 반투명 유리 조각** 몇 개로만 존재하며, 안전 요소(비상정지·주행 상태)만 채도를 가진다.

세 층 모델(그리는 순서이자 우선순위):

```
L0 콘텐츠   카메라 / LiDAR 지도 / 플레이트(정보 화면 바탕)   — 전면, 테두리 없음
L1 유리     나브 필, 텔레메트리, 플로팅 버튼, 시트, 토스트 — 반투명, 모서리 16, 외곽선 없음
L2 안전     주행 상태 캡슐(상단 중앙), 비상정지(우하단)   — 유일하게 채도 있는 채움, 항상 최상위
```

참고 원칙(아트워크 모사 아님):
- DJI Fly/Pilot: 영상 100 %, 상단 얇은 상태줄 하나, 비행 상태는 **상단 중앙 한 덩어리**, 조작은 가장자리에 띄운 작은 버튼. → 주행 상태 캡슐 상단 중앙, 텔레메트리는 우상단 한 줄.
- Skydio / Spot 태블릿: 지도·영상 전환은 **PIP 탭**, 위험 조작은 홀드. → 레이더 PIP를 탭하면 지도 화면.
- Steam Deck / Switch 시스템 UI: 큰 아이콘, 라벨 1~2단어, 넉넉한 간격, 선택은 **테두리가 아니라 채움 밝기**. → 세그먼트·나브 필의 선택 표현.
- 자동차 HMI(2초 글랜스): 상시 요소 최소, 숫자는 크고 단위는 작게. → 로그 화면 빅넘버.
- rviz / Foxglove: 어두운 바탕 위 점유격자, 스캔은 밝은 점, 격자 1 m. → §4.2 LiDAR 지도.

- 선은 `line`/`glass_hi` 1 px뿐. 포커스 링(패드 내비 시) 2 px `text1`.
- 터치 타깃: 필 버튼 h 48(72 px), FAB 56 Ø(84 px), 나브 필 항목 56×44(84×66 px), 비상정지 128×128(192 px), 키패드 64 h(96 px), 지도 줌 버튼 56.

### 2.3 유리 패널 레시피 (ImGui 드로우 리스트, 블러 없음)

```

  1 dl->AddRectFilled(p0+(0,4s), p1+(0,4s), rgba(0,0,0,0.28), r)   // 접촉 그림자 1장(미디어 위에서만 보임)
  2 dl->AddRectFilled(p0, p1, glass, r)                               // 바탕 α0.66
  3 dl->AddRect(p0+(0.5,0.5), p1-(0.5,0.5), glass_hi, r, 0, 1.0f)      // 안쪽 스트로크

  dl->AddRectFilledMultiColor(...)                                     // 라운드 불필요한 전폭 띠
```

왜 블러 없이도 되는가: (1) 유리가 놓이는 위치가 **스크림 위**(화면 위·아래 140/200 px)라 뒤 영상이 이미 어둡다. (2) 유리 α 0.66 + 글자 `text1`은 어떤 영상 위에서도 4.5:1 이상. (3) 가운데 영상 영역에는 유리를 두지 않는다(레이더 PIP 제외, PIP는 원형 비네트).
실제 블러가 필요해지면(§6 S10 선택): 카메라 텍스처를 **1/8 크기 RT에 2-pass 가우시안**으로 10 Hz(카메라 fps)마다 한 번만 내려 두고, 유리 바탕을 `AddImage(blurred, p0, p1, uv=p0/W.., tint glass)`로 그린다. 비용 ≈ 160×90 픽셀 셰이더 2회/0.1 s → 무시 가능. 카메라 위 유리에만 적용되고 지도·플레이트 위에는 불필요하다.

### 2.4 모션(v1 유지 + 추가)
- 나브 필 선택 인디케이터 160 ms ease-out 슬라이드. 화면 전환 자체는 즉시(크로스페이드 없음 — 안전 정보 지연 금지).
- FAB·필 눌림: 즉시 `ctl` 0.18, 떼면 80 ms 복귀.
- 토스트: 120 ms 등장(아래서 8 px) · 4 s · 200 ms 페이드. 하단 중앙, 비상정지 왼쪽 영역.
- 시트: 180 ms 아래서 올라옴, 스크림 α 0.4. 시트 열림 중에도 비상정지는 시트 위에 그린다.
- 지도 따라가기 카메라: 위치 1차 지연 120 ms(10 Hz 자세 갱신의 계단을 숨김). 줌 변경 160 ms.
- 레이더·지도 스윕 애니메이션 없음. 0.35 m 근접 시 로봇 마커 바깥 링 1회 0.6 s 확장(기능적 신호).

## 4. 컴포넌트 명세 (드로우 리스트 기준)

모든 위젯은 v1처럼 `InvisibleButton → 상태 읽기 → 드로우 리스트`. `s = w::S()` 배율, 아래 치수는 논리.

### 4.1 안전 요소
- **`estop_v2(id, 128)`**: 외곽 노란 링 → 사각 r28. 비작동: ① `AddRect(p0-3, p1+3, warn, r+3, 0, 3)` ② `AddRectFilled(p0,p1, danger, r)` ③ `ShadeVertsLinearColorGradientKeepAlpha(danger → danger_deep)`(유일하게 남기는 그라데이션: 버섯머리의 입체) ④ 팔각 `AddNgonFilled(c-(0,14), 22, white α0.92, 8)` + 안쪽 `AddNgon(danger_deep)` ⑤ `비상정지` estop 22 Bold white y+30 ⑥ Ⓑ 글리프 배지 우상단. 미연결: 채움 `ctl`, 글자 text3, 링 `line`. 작동(해제 모드): 채움 bg1, 링 danger 0.8 s 깜빡 2회 후 고정, 중앙 진행 링 r 36 두께 6 `ctl`→ok 호, 자물쇠 아이콘 28, `해제` headline, `1초 누르기` caption. 로직(`estop_button()`의 홀드 계산) 무변경.

### 4.2 LiDAR 지도 — `LidarView` (새 파일 `src/win/lidar_view.{hpp,cpp}`)

데이터 입력(`RobotSnapshot` 확장, §5 S3):
- `OccGrid { int w,h; double res, ox, oy; std::vector<int8_t> cells; uint64_t seq; double rx; }` ← `/map`
- `Pose2D { double x,y,yaw; double stamp; }` ← `/lidar_map/pose`(yaw = atan2(2(wz+xy), 1−2(y²+z²)))
- `ScanData` 기존 ← `/scan`
- `PathStatus` 기존 ← `/api/path`
- 트레일 링버퍼 `std::deque<Pose2D>` 최대 900개(10 Hz × 90 s), 직전 점과 0.03 m 이상 떨어질 때만 push.

좌표: 지도 프레임 x→화면 오른쪽, y→화면 위(north-up, 기본). `to_screen(m) = center + ((m.x − cam.x)·ppm, −(m.y − cam.y)·ppm)`. 셀 (row i, col j)의 좌표 `x = ox + (j+0.5)·res, y = oy + (i+0.5)·res`. 텍스처 UV는 행이 y 증가 방향이므로 그릴 때 v를 뒤집는다(`uv0=(0,1), uv1=(1,0)`).

줌 레벨(단일 터치라 핀치 없음): ppm ∈ {20, 40, 80, 160} 논리 px/m. 기본 **80**(화면 가로 16 m). 20은 30 m 전체가 세로 600에 들어간다. ⊕⊖ FAB로 단계 이동, 160 ms 보간.

그리기 순서와 호출(프레임당):
1. 바탕 `AddRectFilled(bg0)`.
2. **지도 텍스처** 1회 `AddImage(map_tex, to_screen(ox,oy+h·res), to_screen(ox+w·res,oy), uv 뒤집음)`. 선형 샘플링 그대로(확대 시 셀 경계가 부드럽게 번져 글로우와 어울림).
   텍스처 합성(백그라운드, `/map` 수신 시에만, 2 s마다 ≤ 1회):
   - 셀 → RGBA: −1 → (0,0,0,0) · 0..49 → `free` α0.9 · 50..100 → `occ` α 1.0(값 비례 없이 2단계. 임계 50은 rviz 기본과 같다).
   - 점유 마스크를 8-bit로 뽑아 **분리형 박스 블러 r=2 두 번**(≈가우시안) → 할로 알파. 최종 = 코어 위에 `occ_glow`·할로를 "screen" 합성. 600×600 기준 CPU ≈ 2–4 ms, UI 스레드 밖.
   - 업로드 `Texture::update` 1.44 MB. GPU 비용 무시 가능.
3. **격자**: 화면에 보이는 범위에서 1 m 선 `AddLine(grid1, 1)`, 5 m마다 `grid5`. ppm 20에서는 1 m 선 생략(5 m만). 최대 선 ≈ 70개.
4. **스케일 바**: 좌하단 (20, 520). 길이 = 1 m(ppm ≥ 40) 또는 5 m(ppm 20). 양끝 눈금 h 8, 라벨 caption text1 `1 m`, 뒤에 작게 `80 px/m` text3.
5. **실행 중 경로**(`/api/path`): 지난 구간 text3 2 px, 남은 구간 info 3 px, 현재 목표 warn 원 Ø 22 + ink 테두리. 기존 로직 유지.
6. **트레일**: 최근 900 자세를 4구간으로 나눠 `AddPolyline`(accent α 0.55 / 0.35 / 0.18 / 0.08), 두께 3.
7. **스캔 원(FOV)**: 로봇 중심 r 3 m `AddCircle(scan α0.10, 96, 1)`, 채움 `AddCircleFilled(scan α0.03)`. 스캔이 1 s 이상 오래되면 원을 warn 점선으로.
8. **스캔 점(포인트 스프라이트)**: 시작 시 32×32 RGBA 방사형 감쇠 텍스처 1장 생성(중심 1.0, 반지름 0.5에서 0.35, 가장자리 0). 각 빔(≤ 450): `r·cos(θ+yaw)+x, r·sin(θ+yaw)+y` → `AddImage(sprite, p−6, p+6, tint)`. tint = `scan`(기본), `scan_near`(r < 0.35 m, 크기 10), text3(스캔 stale). 450 쿼드 = 1800 정점, 텍스처 1종이라 드로우 콜 1–2개. 범위 ≤ 0.05 m 또는 > range_max 제외.
9. **로봇 마커**: 흰 원 Ø 20 `AddCircleFilled(white)` + 바깥 `AddCircle(bg0 α0.6, 2)`; 머리 쐐기 `AddTriangleFilled` accent 길이 18 (yaw 방향); 몸체 외곽 0.226×0.149 m 회전 사각 `AddQuad(white α0.6)` (ppm ≥ 80일 때만). 근접(< 0.35 m) 시 `scan_near` 링이 0.6 s에 Ø 20→60 확장 1회.
10. **스케치 레이어**: 진행 중 스트로크 `AddPolyline(accent α0.85, 4)`; 확정 경유점(최대 20): 선 ok 2 px(구간 유효) / danger 점선 3 px(점유 통과) / warn 점선(미지 통과), 점 Ø 24 bg0 채움 + 2.5 px 테두리(색은 구간 판정) + 번호 `label`. ①은 로봇 바로 옆이므로 번호 대신 작은 점, 마지막은 깃발 아이콘 `E7C1`(Flag) 또는 숫자 + 이중 링.
11. **HUD**: 나브 필, 캡슐, 텔레메트리, 모드 필, 보내기 필, FAB, 비상정지, 토스트.

경로 유효성 판정(경고 전용, 로봇이 결정): 각 구간을 res/2 간격으로 샘플 → 셀 값 ≥ 50이면 `occupied`, −1이면 `unknown`, 아니면 점유셀에서 0.15 m(3셀) 이내면 `tight`. 구간 색과 보내기 필 문구에 반영. 보내기는 막지 않는다(기존 `send_path` 규칙 유지: `v2.state == idle`일 때만).

**그리기 vs 이동(단일 터치)** — 기본 규칙(결정 D5):
- 손가락이 **로봇 마커 반경 1.0 m(화면 Ø ≤ 160)** 안에서 시작 → 그리기. 그 밖에서 시작 → 팬(따라가기 자동 해제, ◎ FAB가 비강조로 바뀜).
- 모드 필 `[✎ 그리기 | ✋ 이동]`로 강제 가능(필이 "그리기"면 어디서 시작해도 그리기 — 로봇이 화면 밖일 때 필요).
- 로봇 주변 Ø 160에 아주 옅은 `accent α0.08` 원 + 첫 진입 시 1회 토스트 `로봇 옆에서 끌어 경로를 그리세요`.
- 경로 실행 중(`rotate/drive`)에는 그리기 불가(기존), 터치는 팬만.
- 스트로크 종료 → 기존 `sketch_to_path()`(RDP, ≤ 20점) → 유효성 판정 → 보내기 필 등장. 지우기는 ⋯ 시트 또는 새 스트로크 시작.
- 팬 중 관성 없음(1 프레임 지연도 없이 손가락을 따라감). 따라가기 재개는 ◎ FAB.

따라가기/자유: `follow_` 기본 true. 팬 시작 시 false. ◎ 탭 → true + 160 ms 보간으로 로봇 중심 복귀. 로봇이 화면 밖이면 가장자리에 accent 화살표 + 거리 `3.4 m`.

### 4.3 주행 화면 레이더 — 지도와 같은 시각 언어
- `draw_radar()`를 `LidarView::draw_radar(center, radius_px, range_m=3)`로 통합: **같은 스프라이트·같은 색·같은 근접 규칙·같은 로봇 마커**. 차이는 좌표계뿐(로봇 중심·heading-up·회전 없음).

- 지도 텍스처의 로봇 주변 3 m 조각도 함께 보인다(`AddImage`에 uv를 로봇 중심 ±3 m로 잘라 넣고 `PushClipRect` 대신 **원형 마스크가 필요 → 원형 마스크는 ImGui로 불가하므로 생략하고 사각 uv를 α0.5 로 그린 뒤 가장자리 비네트 링 4겹(`AddCircle` 두께 6, glass α 단계)으로 모서리를 덮는다**. 비용 ≈ 5 드로우.
- 상태 라벨 `LiDAR 3 m` / `SCAN 없음`은 원 아래 바깥 caption. 탭 → 지도 화면.

S1–S4까지(≈22 h)가 끝나면 "박스 투성이 데스크톱 툴" 인상과 "로봇이 그린 JPEG 지도" 두 가지가 모두 사라지므로 여기서 사용자 실기 점검을 받는다.

성능 예산(지도 화면 최악): 지도 텍스처 1 드로우 + 격자 ≤ 70선 + 스캔 450 쿼드 + 트레일 4 폴리라인 + 경유점 20×(원 2 + 글자) + HUD ≈ **정점 1.5만, 드로우 콜 < 25**, 120 Hz에서 충분. 지도 텍스처 합성은 2 s마다 UI 밖 스레드. `/map` JSON(약 1–1.4 MB 텍스트) 파싱은 수신 스레드에서 ≤ 30 ms, 기존 `kMaxMessage` 8 MB 안.

리스크: ① rosbridge `compression:"png"`의 실제 페이로드 형식(PNG 안에 JSON 바이트)을 S3 첫 시간에 실기로 확인하고, 실패하면 비압축 JSON으로 간다(2 s 주기라 허용). `cbor`는 미확인 대안으로만 기록. ② `/lidar_map/pose`와 `/scan`의 타임스탬프 차이(≤ 100 ms)는 0.25 m/s에서 2.5 cm 오차 — 무시하되 로그 화면에 skew를 표시. ③ 선형 샘플링된 지도 텍스처가 ppm 160에서 흐릿하면 포인트 샘플링 SRV를 하나 더 두고 ppm ≥ 160에서 전환(D3D11 샘플러는 ImGui 백엔드 기본이 선형이므로 `ImDrawCallback`으로 샘플러 교체 1회). ④ 카메라가 16:9로 바뀌면 HUD가 영상 위에 놓이는데 스크림이 이를 전제로 설계돼 있다.
