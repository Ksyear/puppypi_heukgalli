# 코드 둘러보기 — 면접에서 설명할 수 있게

포트폴리오를 보는 사람이 가장 많이 물을 코드 다섯 곳과 보안에서 한 일, 그때 할 수 있는 답을 정리했다. 각 절은 "어디(파일·함수) → 무엇을 → 왜 그렇게" 순서다.

## 1. 운전을 허용할지: `decide_drive()` — `src/v2client.cpp`

- **무엇**: 20 Hz 송신 때마다 "이번 명령을 활성(움직임)으로 보낼지"를 정하는 순수 함수. 입력은 데드맨(RT)·축 값·입력 신선함(0.25 s)·ACK 신선함(0.6 s)·로봇 상태·비상정지·재프레스 요구.
- **왜 순수 함수**: 안전 규칙이 한 곳에 모이고, 스레드·소켓 없이 전이 표 전체를 단위 시험할 수 있다(`test_drive_decision`).
- **안전 3층**: ① 앱: 데드맨·포커스 상실·입력 끊김 → 중립 ② 프로토콜: 로봇이 중립 확인 전 활성 명령을 거부 ③ 로봇: 0.4 s watchdog. 앱이 죽어도 ③이 멈춘다(로봇 저장소 문서의 개발 컨테이너 시험: 조종기 강제 종료 뒤 0.32 s 정지. 실기 미확인).
- **재프레스 규칙**: 비상정지 해제 직후 RT 를 쥐고 있으면 움직이지 않는다. 한 번 놓아야 풀린다(의도하지 않은 출발 방지).

예상 질문: "UDP 인데 패킷이 사라지면?" → 명령은 20 Hz 로 계속 덮어쓰므로 하나 잃어도 다음 것이 온다. 로봇은 0.4 s 동안 아무것도 못 받으면 멈추고, 앱은 ACK 가 0.6 s 없으면 스스로 중립을 보낸다. 비상정지는 번호를 올려 두 번 보낸다.

## 2. WebSocket 을 직접: `RosBridge` — `src/rosbridge.cpp`

- 라이브러리 없이 RFC 6455: 핸드셰이크, 클라이언트 → 서버 마스킹, 126/127 확장 길이, 조각(fragment) 이어 붙이기, ping→pong.
- **큰 메시지 처리**: `/map` 은 JSON 으로 약 1.4 MB. `compression:"png"`(rosbridge 가 JSON 바이트를 PNG 픽셀에 담음)로 받아 약 10 KB 로 줄이고, `"op":"publish"` 의 토픽을 앞부분만 보고 알아낸 뒤 `RawFn` 으로 넘겨 일반 JSON 트리를 만들지 않는다.
- **보안 상한**: 프레임·누적 메시지 8 MiB. 소켓 닫기는 뮤텍스 아래에서(다른 스레드가 닫힌 번호를 재사용하는 경쟁 방지).

예상 질문: "왜 라이브러리를 안 썼나?" → MinGW 정적 단일 exe, 의존성 0 을 원했고, 필요한 범위(텍스트 프레임, 조각, ping)가 작았다. 대신 상한과 시험으로 위험을 줄였다.

## 3. LiDAR 지도 해석: `parse_occupancy_grid()` — `src/lidar.cpp`

- `"data":[` 를 찾아 정수 36만 개를 `strtol` 로 직접 읽고, 나머지(`info`)만 일반 JSON 으로 해석한다. 일반 해석기는 값마다 객체를 만들어 수십 MB 를 잠깐 쓰기 때문이다.
- 그린 결과는 `ui_draw.cpp` 의 `raster_grid()` 가 작업 스레드에서 RGBA(점유 칸 코어 + 박스 블러 할로)로 만들고, UI 는 다 된 것만 올린다. 흑갈리에서 지도 화면 프레임 최대가 12.9 ms → 2–4 ms 로 줄었다.

## 4. 장애물 회피: `plan_path()`·`nav_loop()` — `src/planner.cpp`, `src/robot.cpp`

1. **비용 격자** `CostGrid::build`: 출발·경유점 범위 + 3 m 를 0.10 m 칸으로. 지도 점유(≥ 65)·실시간 스캔 점을 장애물로 찍고, 두 번 훑는 chamfer 거리 변환으로 "가장 가까운 장애물까지 거리"를 구한다. 거리 < 0.20 m(로봇 몸 + 여유)는 막힘, 그 바깥 0.35 m 는 비용을 더해 가운데로 지나가게.
2. **구간별 계획**: 그린 선의 각 구간이 비어 있으면 그대로, 막혔으면 그 구간만 A*(8방향, 모서리 끼기 금지). 결과에서 "보이는 데까지 건너뛰기"로 꺾이는 점만 남기고 20개를 넘으면 가장 덜 휘는 점부터 뺀다.
3. **가는 중**: 새 스캔마다 남은 경로 앞 1.6 m 를 `path_blocked_by()` 로 본다. `BlockTrigger` 가 4번 중 3번(한 번 튄 값 무시) + 1.5 s 쿨다운을 판단하면 `path_cancel` → 막힌 점 20 s 기억 → `remaining_goals()` 로 아직 안 지난 경유점까지 다시 계획 → 로봇이 중립(idle)일 때 새 `path`.
4. **안전**: 사용자가 스틱을 쓰거나 비상정지하면 회피 주행은 즉시 끝난다. 로봇이 스스로 취소하면(watchdog 등) 앱은 다시 보내지 않는다 — Tailscale 중계에서 유실 25–56 % 일 때 실제로 이렇게 멈췄다.

예상 질문: "왜 로봇에서 안 하고 앱에서?" → 로봇 소프트웨어를 바꾸지 않는 것이 이 프로젝트의 전제였다. 대가는 네트워크 지연만큼 반응이 늦다는 것(README 한계 절). 로봇 쪽 회피가 생기면 앱 계획기는 "보내기 전 우회"만 남기면 된다.

## 5. 화면과 스레드: `Robot::snapshot()`·`ui_draw.cpp`

- 네트워크 스레드 여러 개가 쓰는 상태를 UI 는 프레임마다 `snapshot()` 으로 **한 번 복사**해 읽기만 한다. UI 가 잠금을 오래 잡지 않아 120 Hz 가 유지된다(평균 0.6–1.0 ms/프레임).
- 입력·안전(`ui.cpp`)과 그리기(`ui_draw.cpp`)를 파일로 나눴다. 디자인을 두 번 갈아엎는 동안 안전 로직은 한 줄도 바뀌지 않았고, 매번 같은 시험이 통과했다.
- 디자인: v1(기본 ImGui 룩) → v1.5(토큰·아이콘) → v2 "검은 유리 조종석"(콘텐츠 전면 + 떠 있는 유리 조각). 근거는 `docs/DESIGN_PLAN_v1.md`, `v2.md`.

## 6. 보안에서 한 일

- 코드: 메시지·JPEG·해상도·스캔 크기 상한, 소켓 경쟁 수정, 출처 없는 ACK 무시, 로봇 이름 제어 문자 제거, 키보드 운전은 `--kbdrive` + Shift 데드맨일 때만.
- 빌드: 스택 보호, FORTIFY, 형식 문자열 오류화, CET, ASLR/DEP/고엔트로피 VA. 흑갈리의 GCC 가 기본 매니페스트를 몰래 하나 더 넣어 exe 에 매니페스트가 두 개(UTF-8·DPI 설정이 무시될 수 있음) 들어가던 것을 링크 경고에서 찾아 막았다(`Makefile`).
- 서명 없는 exe 라 Windows Smart App Control 에 막힌다는 것을 배포 전에 알게 됐고, 그 대가(기기 보안 하나를 끄는 일)를 README 에 적었다.
